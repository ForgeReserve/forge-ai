# The natural voice (on-device text to speech)

Status: built on branch `v2-voice` (plan: the voice bake-off). Measured with the voice lab on an iPhone, a Pixel 8 Pro and a Mac (2026-11-14), and on a Galaxy A16 5G, where the Android app now makes the voice with native code (2026-11-15, below); the device the app picks follows from those numbers.

The v2 app reads answers aloud with **Phonon 31m English** (Gradium, Apache-2.0), a 31M-parameter streaming text to speech model, through Gradium's browser package **phonon-tts 0.7.0** (MIT OR Apache-2.0). The model runs in a worker in the page. The answer text is not sent anywhere, and there is no charge.

## Where the files come from

| What | Where it lives | How it gets there |
|---|---|---|
| phonon-tts 0.7.0 (JS, 4 wasm builds) | `public/v2/vendor/phonon-tts/` (committed, about 16 MB) | `scripts/vendor-phonon.sh`: pnpm in a throwaway folder with the 3-day release-age rule, install scripts off, integrity checked |
| Phonon 31m: `model.q8.gguf`, `tokenizer.json`, `config.json` | `public/v2/voice/phonon/31m-en-92741c5/` (not committed) | `node scripts/phonon-model.ts`, at build time |
| The app's two en-GB female voices, Maeve (default) and Freya | `public/v2/voice/phonon/voices-0ee1720/` (not committed) | the same script |
| Five more en-GB female voices and five accent-test voices, voice lab only | the same folder (not committed) | the same script |
| `index.json` (what the app reads) | `public/v2/voice/phonon/index.json` (not committed) | written by the script once every file checks out |
| Licences | `public/vendor/licenses/phonon-tts.txt`, `phonon-tts-THIRD_PARTY_LICENSES.md`, `phonon-models.txt` | committed |

`scripts/phonon/lock.json` pins every file to a Hugging Face commit (`gradium/phonon-31m-en@92741c5b`, `gradium/phonon-voices@0ee17205`) with its size and SHA-256. The script downloads into `.tmp/phonon-download/`, checks size and hash, and only then moves a file into `public/`. It refuses any repo but `phonon-31m-en` (the 40m models are CC BY-NC) and any URL that is not pinned. `--check` checks without the network.

The Docker image runs the script during the build, and so does every Android build (`scripts/android-web.ts`). The app never asks Hugging Face for anything: phonon-tts is always handed a model on the app's own address, never its default model (a test checks no app file names Hugging Face).

## How it runs

- **Voice out module** `forge.voice-out.phonon` (`public/v2/modules/voice-out/phonon/`): `private()` true, `price()` 0. It streams each 80 ms piece of sound to the speaker adapter's `stream()` (Web Audio) as the model makes it, so reading starts before the sentence is done. Stop aborts the stream and silences the speaker at once.
- **The engine wrapper** `public/v2/core/phonon.js`: reads `index.json`, checks the browser can run the model (WebAssembly SIMD and module workers), knows whether the model is downloaded, and loads it once.
- **Choice:** More, Voice lists Natural voice, Phone voice, Engine voice and Off. Until the person picks one, answers are read with the natural voice where the phone runs it, else the phone's own voice, else the engine's (`pickVoiceOut`, setting `auto`).
- **Speaker:** while the natural voice is the one in use, More, Voice also offers its speaker: **Maeve** (the default) or **Freya** (setting `naturalVoice`, `''` for the default). These two are the lock's `voices`, the only ones the app's model is handed. The other five en-GB voices (Pippa, Elodie-Rose, Imogen, Lottie, Bryony) are `labVoices` with `use: "lab-only"`: the voice lab offers them under "Other voices, lab only" to compare by ear, the app never does. A speaker picked before the first use is the one the first download fetches (the same 256 KB as Maeve); another is fetched the first time it reads.
- **First use on the website:** Listen speaks at once (owner, 2026-11-15). While the natural voice is not on the phone yet, the phone's own voice reads the answer, and the natural voice is offered under Listen as an upgrade (Better voice, its size, about 65 MB: the model and the default voice, with Get and Not now; `core/talkctl.js`). Not now is kept on the phone (`naturalNotNow` in the settings), so it is not offered on every Listen; More, Voice still picks the natural voice. Only a phone with no voice of its own asks before the download, as before: Not now reads nothing, and answers to spoken questions are then not read on their own until the person taps Listen, which asks again. A question asked by voice also carries a voice instruction to the model (short, plain, no Markdown: `system.prompt.voice`), and whatever is read aloud has its Markdown, addresses and emoji taken out first (`core/speech.js` `speakable`). After Download (or Get), a window shows the download as it goes (below) and closes once the voice starts reading. phonon-tts keeps the files in Cache Storage (`phonon-tts-v1`), so later uses load from the phone.
- **Download progress:** a bar with MB done of MB in all and the percent, then the phase in words: Downloading, Getting ready (every byte is here and the model is being set up), and in the voice lab Reading line 3 of 10. The numbers are phonon-tts's own progress reports (`onProgress`, one stream of `{file, loaded, total, cached}` per file), added up by `createMeter` in `core/phonon.js` over the files a load reads: the weights, the tokenizer, the config and the voice it starts with. A file's size is the server's `Content-Length`, or the size the lock pins when there is none; a file read from the cache counts as done at once. The package still fetches and caches the files itself, so Cache Storage and offline use are as before. A failed download says so ("The download stopped. Check the connection and try again.") with Try again; in the app Try again does not ask the download question a second time, and Hide leaves the download running (Listen shows the percent).
- **Sound on iPhone:** iOS (Safari, and every browser there) starts Web Audio only inside a tap. A context made or resumed later, after an await, stays suspended: it plays nothing and never ends a sound. So the speaker (`core/adapters.js`) keeps one Web Audio context for the page, and `speaker.unlock()` (make or resume it, and play one sample of silence) runs first, before any await, in every tap that leads to sound: Run in the voice lab, Listen, Download, Try again, and pressing and letting go of the talk button (the answer to a spoken question is read after the release). While it plays, a stream sets the iOS 17+ audio session to `playback`, so the ring switch on silent does not mute it, and puts back `auto` after. A stream whose context never runs ends on a timer rather than waiting for ever, and if the sound is still off when the voice is ready, the answer screen says "Tap Listen to hear the answer" and the lab measures without playing and says so.
- **Offline:** the voice package lives under `/v2/` so the v2 service worker controls its worker too (a service worker only controls a worker whose script is inside its scope). The package files are kept by the service worker; the model files are left to phonon-tts's own cache, so they are not kept twice. Tested: after one use, the app reloads and reads aloud with the network off.
- **Threads:** the gateway serves `/v2/` and `/vendor/` with `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp` and `Cross-Origin-Resource-Policy: same-origin` (`src/app.ts`), so the page is cross-origin isolated and the model runs on 3 threads. `/vendor/` needs them because pdf.js starts a worker from there, and an isolated page cannot start a worker without them. Without isolation, phonon-tts runs on one thread.
- **Android:** the APK carries the model and voices (stored uncompressed, `noCompress 'gguf', 'safetensors'`), read straight from the APK, never copied into Cache Storage, so the first open reads aloud with no download. `MainActivity` adds the same isolation headers to the app's own files (`IsolationRules.kt`). If the very first page load came up without them, the page reloads once (`reloadForIsolation`).

## Where it runs (measured)

The voice lab on real phones, 2026-11-14, voice Maeve, 3 short lines each (first sound is the median; RTF is time per second of sound, under 1 keeps up):

| Phone | Browser | Processor, threads | Processor, one thread | Graphics chip (WebGPU) |
|---|---|---|---|---|
| iPhone, iOS 18.7, 4 cores, WebGPU vendor `apple` | Safari 26.6.1 | 38 ms, RTF 0.147 | 53 ms, RTF 0.203 | **27 ms, RTF 0.045** (load 8.0 s first, 3.2 s again) |
| Pixel 8 Pro, GrapheneOS, 9 cores, WebGPU vendor `arm`, architecture `valhall` | Chrome 155 | **36 ms, RTF 0.220** (load 21.4 s first with the download, 4.1 s again) | 46 ms, RTF 0.294 | 179 ms, RTF 0.461 (load 11.4 s again) |
| Mac, 8 cores, WebGPU vendor `apple` | Safari 26.5 | **26 ms, RTF 0.084** | 32 ms, RTF 0.171 | loaded (3.3 s) but read no line and said no error: a lab bug, see The voice lab |

So the app picks (`chooseVoiceDevice` in `core/phonon.js`, a pure function with a unit test per case):

1. **WebGPU** when the adapter's vendor is `apple` and it is not a software fallback adapter (on Apple's chips WebGPU is 3 times faster than threads).
2. Otherwise the **processor with threads** (`threads: 'auto'`) on a cross-origin isolated page (on the Pixel's Mali, WebGPU is 2 times slower than threads; every other vendor is unmeasured, so it gets the processor too).
3. Otherwise the **processor on one thread**.

On WebGPU the app asks phonon-tts for `device: 'auto'`, so a WebGPU that fails to start falls back to the processor inside the same worker, with the files it already downloaded. If WebGPU fails to start, or on its first use errors, ends with no sound, or makes no sound within 20 s (`GPU_FIRST_SOUND_MS`), the app frees it, reads the same line again on the processor (threads where the page is isolated), stays there for the rest of the session, and remembers it in the settings (`voiceDevice: 'cpu'`), so the next start goes straight to the processor without asking for an adapter. Erase everything clears that, like every setting. The voice lab shows which the app would pick ("The app reads with") and saves it in its results (`env.appDevice`); the lab itself still runs each way exactly as asked, with no fallback.

## Native voice in the Android app

Measured with the voice lab on a Galaxy A16 5G (SM-S166V: Exynos 1330, `s5e8535`, 2 Cortex-A78 at 2.4 GHz and 6 Cortex-A55 at 2.0 GHz, 4 GB; CPU parts `0xd41` and `0xd05` in `/proc/cpuinfo`), in the browser: the processor on 3 threads read 60 lines at RTF 0.937 median (p90 1.316), rising from about 0.86 to 1.34 as the phone warmed up, with 1236 gaps; WebGPU (ARM Valhall) at 1.93. Not usable. So inside the Android app, where the phone can run it, the natural voice is made by native code instead:

- **The runtime:** Gradium's own C interface to Phonon, `libptts_ffi.so`, from [xn-ptts](https://github.com/gradium-ai/xn-ptts) (MIT OR Apache-2.0) at tag v0.7.0, commit `32c1554a` (2026-11-09, the same release as the vendored phonon-tts 0.7.0; v0.7.1 was one day old). Upstream's Android route is that library plus a Kotlin wrapper over JNA; the app calls the same C functions through a small JNI file of its own (`android/app/src/main/cpp/forge_ptts_jni.c`, built into `libforge_ptts.so`), so there is no JNA and no reflection. Strings cross as UTF-8 bytes, so an emoji in an answer reaches the model intact.
- **The build:** `scripts/android-ptts.sh` clones xn-ptts into `.tmp/ptts-build/` (not committed), checks out the pinned commit and builds with cargo-ndk 4.1.2, NDK 27.1.12297006, API 28, arm64-v8a only, `--locked` against upstream's `Cargo.lock`: release, fat LTO, one codegen unit, symbols stripped, 16 KB page alignment, `-C target-cpu=generic -C target-feature=+dotprod,+fp16` as upstream's `android/build.sh` (NEON is the arm64 baseline; xn picks its int8 dot-product kernels at compile time; xn's only other ARM switch, `kai`, is SME2, which no phone here has). The files are committed in `android/app/src/main/jniLibs/` with their sizes and SHA-256 in `scripts/ptts/lock.json`, so the Gradle build and CI need neither Rust nor the NDK; `test/unit/android.test.ts` checks every file against the lock. Two clean builds gave the same bytes. `libptts_ffi.so` is 5,868,752 bytes, SHA-256 `b2f6b99e5ceb68672df3687a55c4144b7f301717c7a2649a620fc0e81dbcfe53`; `libforge_ptts.so` 8,456 bytes, `a88c2e2f2209cdf4eee62b70febb720340a5d42ba8047c45e08f0119add5b659`.
- **Other ABIs:** Android refuses to install an APK whose native libraries are all for ABIs the phone lacks, and 32-bit Android Go phones are among the slow phones this is for. So `armeabi-v7a`, `x86` and `x86_64` each carry an empty placeholder (`libforge_noabi.so`, a few KB, also in the lock), and there the app reads with the browser's build.
- **Which phones:** the library needs ARMv8.2's dot product and half floats on every core (`asimddp`, `fphp`, `asimdhp` in `/proc/cpuinfo`; Cortex-A55 and A78 have them, A53 does not) and crashes without them, so `ForgeVoice.status` checks first (`VoiceRules.cpuOk`) and also that the app was installed with its arm64 libraries. Otherwise, or after the voice process crashed or failed to load once this session, the browser's build reads.
- **The model:** the same files the APK already carries for the web view (`public/v2/voice/phonon/`). The library loads a checkpoint folder by path (`ptts_new(dir)`) and cannot read inside the APK, so the first use copies them once into the app's no-backup storage, laid out as that folder (`config.json`, `tokenizer.json`, `model.q8.gguf`, `voices/<Name>.safetensors`, 67 MB; 0.8 s on the A16), and keeps them until the model's revision changes. That is the space twice; there was no way around it without changing the library.
- **The process:** the model runs in a process of its own, `:voice` (`VoiceService`), bound important by the app so it gets the foreground cores (`/top-app`). Two reasons: the runtime's worker pool is built once per process with the thread count read before the model loads (`RAYON_NUM_THREADS`), so another thread count is another process; and a crash in native code ends only that process. The voice process plays the sound itself through an `AudioTrack` (24 kHz float); no sound passes through the page.
- **Threads:** as many as the phone has fast cores (the cores with the highest top clock), pinned to them, never fewer than 2 or more than 4 (`VoiceRules.defaultThreads`, `pinFor`); `ForgeVoice.config({threads})` changes it (in the voice lab, "Threads the native voice uses in the app"). On the A16 that is 2 threads on the two A78 cores, which measured best (below).
- **Web side:** `core/native.js` `nativeVoice` (status, speak, stop, bench, config, release, saveLab); `createPhonon({nativeVoice})` offers it as `native()`, and the natural-voice module uses it in the app, else the browser's build.

Galaxy A16 5G, the APK on Android, Maeve, the voice lab's native candidates (made without playing), 2026-11-15:

| Way | Lines | First sound, median / p90 | RTF, median / p90 | Model load (process start, copy, load) |
|---|---|---|---|---|
| Native, 2 threads on the fast cores | 60 | 49 / 79 ms | **0.299 / 0.331** (0.24 to 0.35 over the run) | 0.17 s load; first ever 1.8 s with the copy |
| Native, 2 threads on the fast cores | 10 | 40 / 59 ms | 0.266 / 0.368 | 0.17 s |
| Native, 4 threads | 10 | 80 / 94 ms | 0.354 / 0.407 | 0.19 s |
| Native, 6 threads | 10 | 94 / 245 ms | 0.442 / 0.668 | 0.18 s |

Played through the speaker (3 lines, `native-2:3:play`): no gaps and no `AudioTrack` underruns. More threads were slower: the runtime spins between tiny kernels (xn's threadpool notes the same past three threads), and the slow A55 cores hold the fast ones back. The A16's web view in the app is not cross-origin isolated (`crossOriginIsolated` false in the lab), so there the browser's build would run on one thread.

## Slow phones

Wherever the natural voice is made (the browser's build or the native one), the app measures how fast this phone makes it and starts reading only when it will not run dry (`core/voicepace.js`; the native voice runs the same rules and numbers in `VoicePace.kt`):

- **Measured:** the real-time factor (rtf, seconds of work per second of sound) of the first piece of each answer, as the lab counts it, and the seconds of speech per character; kept per way of making the voice in the settings (`voicePace`: `native`, `web-cpu-auto`, ...), each answer moving it 30% (`notePace`). While an answer is made, its own speed counts once 0.32 s of sound has come after the first piece (that piece's delay is left out).
- **Buffering:** at rtf 0.8 or under, playback starts with the first piece. Above it, playback starts once the sound in hand is at least `remaining * (1 - 1/rtf) + 0.5 s`, where `remaining` is all the answer still to play (what is made, and the rest at the seconds per character); with sound arriving at 1/rtf seconds a second, the rest then arrives before it is needed. Meanwhile the answer says "Getting the voice ready" with a small bar (`#speakReady`).
- **Fallback:** when the phone has a voice of its own and the person has not asked to keep the natural voice, an answer goes to the phone's own voice when rtf is over 1.6 or the wait (`buffer * rtf`) would be over 6 s: before it starts, by the kept speed while it is under 30 minutes old (a phone that was hot may have cooled), or as soon as the answer's own speed says so, before anything played. The app says so once a session ("The natural voice is slow on this phone, so the phone's own voice reads this answer ..."). More, Voice has **Keep the natural voice** (`preferNatural`): on, it always waits instead.
- **Tests:** `test/unit/v2/voicepace.test.ts` (the sums; an engine at rtf 0.85 to 1.5 never runs dry; the fallback rule), `VoicePaceTest.kt` (the same numbers), the module in `test/unit/v2/phonon.test.ts` (rtf 1.3 waits and plays with no gap, rtf 2.2 goes to the phone's voice, kept natural voice, the native path and its failures), and `test/ui/phonon.ui.test.ts` "the natural voice on a slow phone": a fake engine at rtf 1.3 in Chrome shows "Getting the voice ready" and its bar, then reads the answer with no gap.

## What cross-origin isolation changes

With `require-corp`, the v2 page may only load other sites' files that opt in. The v2 app loads none: it talks to its engine with CORS requests (allowed), and every script, style, image and worker is its own. Checked with every UI and e2e test passing with the headers on: private (EHBP) answers, Lightning and eCash funding, camera notes, photos shared in, card taps, the Android bundle. Classic (v1) at `/` gets no new headers.

## The voice lab

`/v2/#/voice-lab`, linked from no menu. Press Run to start (the tap also unlocks the sound on iPhone; see above). It reads a fixed corpus of 60 lines (short replies, numbers and money, names, hard cases, long answers; `public/v2/core/voicelab.js`) with each way of reading this phone has: the natural voice on the processor with threads, on one thread, on the graphics chip (WebGPU), and the phone's own voice. Per line: time to the first sound, real-time factor, gaps a listener would hear (from when each piece arrived, or from the real speaker with Play on), NaN or silent sound, clipping. Per way: model load time, first and again, and the memory the browser reports. While the model loads, the download bar and its phases show above the results; a failed download stops the run with Try again (the other ways read the same files). The lab waits for the model to be in the cache before its second load, so it does not download it twice. A way of reading that fails says so in its row and in the saved results (`error`, and per line `error` with `code`). On the Mac (Safari 26.5) the graphics chip loaded in 3.3 s and then gave no row and no error. The cause is not found: this needs a WebKit browser, and none was run here (the iPhone's Safari 26.6.1 and Chrome read on WebGPU fine). In the lab as it was, a way of reading could end with no row and no error only after Stop: a Stop during its second load left no row and no word of it, and an error during a line after Stop was dropped together with its row; a line that hung held the run until Stop. So the likely story is that WebGPU hung, or failed, on its first line and the run was stopped; that is not confirmed. Both gaps are closed. Since then: a line that ends with no sound and no error fails (`code: "no-sound"`) instead of counting as a silent line; a line with no sound for 30 s, at its start or between two pieces, fails (`code: "stalled"`) and ends that way of reading, rather than hold the run for ever; an error is kept even after Stop; a way of reading with no line read, or with every line failed, carries an `error` that the table shows ("Failed: ..."); one stopped before its first line says "Stopped before the first line". The results also carry the adapter's subgroup support and sizes (`env.webgpu`), which decide which kernels phonon-tts runs, for the next Mac run. A test in Chrome hands the worker a WebGPU that loads and reads nothing, and checks the lab shows the failure. The phone's own voice: the browser's voice list is often empty until it has loaded it (iOS Safari), so the lab waits for the `voiceschanged` event (and looks again every 250 ms) for up to 4 s before it says there is none, and counts every English voice the browser marks local (`localService`; WebKit marks every iOS voice local, with languages like `en-GB`, `en-US`, or `en_US` on older WebKit), British first. The Run tap also speaks a silent utterance, since iOS lets a page speak later only once it spoke inside a tap. Each line is said in pieces of at most 200 characters, cut at sentence ends (`splitForSpeech`), because iOS reads long utterances badly; and since iOS often never sends an utterance's `end` (a 60-line run on an iPhone sat on the phone voice for ever), every piece has a deadline of 2.5 times its spoken length at 16 characters a second, plus 5 s (`speakLine`): at the deadline the lab cancels it, records the line with `timedOut: true` and no `audioS` (the summary counts `timedOutRuns`), skips the rest of that line and goes on. A voice that never even starts ends that way of reading with an error. The results list what the browser offered (`listed`). On GrapheneOS, which has no speech engine, it still says there is none. **Stop** ends the run at once, whatever it is waiting on: every wait (a model load, the sound playing, a line of the natural voice, an utterance of the phone voice) gives way to the abort signal (`untilAborted`), speech is cancelled, and a natural-voice model left waiting is freed. The results are kept as each line finishes, so while it runs "Save results so far" and "Copy results so far" save what is done (`partial: true`), and after Stop, Save keeps every line done (the way of reading that was running says `stopped: true`). Save results writes a JSON file to send on (with the voice, its locale, and whether it was an accent test). Kokoro is not in this build (it would need ONNX Runtime Web, a new dependency); its baseline is flash-mobile's measured numbers.

## The first run's Listen clips

The five first-run clips (`public/v2/voice/en/{welcome,pay,limits,private,private-off}.ogg`, Opus in Ogg) are recorded in this same voice, Maeve, so the first words a person hears are the voice the app then reads answers with (they were Kokoro's Emma before, 2026-11-14 owner decision). `scripts/record-voice/record.py` (default `--engine phonon`) hands each step's words to `scripts/record-voice/phonon-render.ts`, which reads them with the vendored phonon-tts in headless Chrome (playwright-core), from the build's own model files (`public/v2/voice/phonon`), on the processor on one thread, seed 4242424242424242 and temperature 0.3 (phonon-tts's own defaults, given explicitly): two runs give the same samples. No speed condition is set, so the clips read at the pace answers do. The Python side pads each clip (0.25 s before, 0.1 s after), scales it down only if it peaks above 0.98, writes Opus, reads the file back and refuses one that is near silent or has a clipped sample. `manifest.json` names the engine, voice, voice file and voice repo commit, model and revision, phonon-tts version, device, seed and temperature, and each clip again carries its `voice` and `model`; `text_sha256` still guards the words. `test/unit/v2/voice-clips.test.ts` checks the words, the files and that the voice is the lock's default (`Maeve`) on the pinned model revision. Licences: Phonon 31m and the voices are Apache-2.0, `public/vendor/licenses/phonon-models.txt` (the clips are made from them, so that notice covers them), phonon-tts in `phonon-tts.txt`. `--engine kokoro` still records with Kokoro's Emma (`public/vendor/licenses/kokoro.txt`); the shipped clips no longer use it. The clips were checked by numbers (peak 0.42 to 0.52, no clipped sample, speech from about 0.4 s to the end, no gap inside over 0.6 s), not heard.

## Speech input on the phone (Android app)

Hold to talk turns the voice into words one of four ways (`voice-in` modules, `pickVoiceIn` in `core/state.js`):

| Module | Where | Private | Price |
|---|---|---|---|
| `forge.voice-in.bundled`, "On this phone" | Forge Private Voice, the APK for GrapheneOS, with its own model (below, Bundled speech to text) | Yes: the sound never leaves the phone | Free |
| `forge.voice-in.phone`, "On this phone" | The Android app, where the phone's on-device recogniser has the language | Yes: the sound never leaves the phone | Free |
| `forge.voice-in.engine`, "Engine" | Anywhere the engine has a speech to text model | With an enclave model (Private only) | Per question |
| `forge.voice-in.device`, "This browser" | A browser with a recogniser, only when picked and Private only is off | No: the browser may send it to its maker | Free |

- **Which is used:** `voiceIn` is `auto` until the person picks one in More, Voice: Forge Private Voice's own model where the APK carries it, else the phone's recogniser where it is offered, else the engine's (with its free voice questions). Both phone ways are one row in More, Voice, On this phone (`voiceIn: 'phone'` keeps the same order). Picked Engine (`voiceIn: 'engine'`, `voiceInPicked: true`) uses the engine first, the phone's only when the engine has no model. Settings saved before `auto` existed carry `engine`, which was the default then, so a saved `engine` without `voiceInPicked` reads as `auto` (`loadedSettings`). On the website there is no bridge, so the phone module is never offered there.
- **The plugin:** ForgeSpeech (`android/.../SpeechPlugin.kt`, rules in `SpeechRules.kt`), ported from flash-mobile's `VoiceInputBridgeModule` (MIT, Galoy Inc.). It uses only `SpeechRecognizer.createOnDeviceSpeechRecognizer` (Android 12, API 31, and up; the app still installs from Android 9 and uses the engine there) and never creates the default recogniser, which may send the sound to a server; there is no fallback to one inside the plugin. Its calls: `available({locale})` resolves `{onDevice, reason, locale}`; `start({id, locale})`, `stop({id})`, `cancel({id})`; events `speech` `{id, type}` with `started`, `level {level}`, `partial {text}`, `final {text}`, `error {code}` and `end`, always last. Error codes: `permission`, `unavailable`, `no-speech`, `busy`, `audio`, `failure`, `interrupted` (the app left the screen).
- **Availability:** below Android 12, `android-older-than-12`; no on-device recogniser on the phone (`SpeechRecognizer.isOnDeviceRecognitionAvailable` false), `no-on-device-recognizer`. On Android 13 and up the plugin asks the recogniser which languages it has (`checkRecognitionSupport`) and offers it only when the language is installed: the same tag, else the same language (asked `en-GB`, has `en-US`: listens in `en-US`). Not offered when the language is still downloading (`language-downloading`), can be downloaded but is not (`language-not-downloaded`), is not there at all (`language-not-supported`), when the check fails (`check-failed-<code>`) or takes over 3 s (`check-timed-out`). Android 12 cannot answer that question, so there it is offered (`languages-unknown`) and a missing language fails at start, after which the engine hears the next question. The page asks once when the app opens (`navigator.language` when it is English, else `en-US`) and redraws when the answer comes. The plugin logs every check: `adb logcat -s ForgeSpeech`. A debug build runs the check from a computer without the page and without listening: `adb shell am start -n com.forgereserve.ai/.MainActivity -e forge.speechCheck en-US`.
- **A press:** press starts the recogniser, the words it hears so far show in the line under the rings as they come (`partial`), and the level bars follow its sound level. The recogniser ends its session by itself after a pause; while the button is still held the plugin starts it again and joins the words (`SpeechSession`, at most 20 times), so a pause does not cut the question short. Letting go stops it: its last result is the question (`final`), sent as it is today. If no last result comes within 4 s, the words heard so far are sent; nothing heard is "Nothing was heard". Sliding off cancels and nothing is sent. Leaving the app drops it. The page gives up waiting after 6 s.
- **The microphone:** the same `RECORD_AUDIO` permission Hold to talk already uses. If the web view has not asked for it yet, the plugin asks the first time (Capacitor's permission request); refused, the talk button says to allow the microphone, as it does for the web microphone. No new permission.
- **Free:** a voice question heard on the phone is priced as a typed one: the line under the rings shows the question's price, and with free questions or a free model and no paid balance it can still be asked, as with the browser's recogniser (no "Add funds" for the speech part).

## Bundled speech to text (Forge Private Voice)

GrapheneOS has no on-device speech recogniser, so there Hold to talk went to the engine. Forge Private Voice is a second APK (the `privatevoice` Gradle flavour, application id `com.forgereserve.ai.privatevoice`, docs/ANDROID.md, Two APKs) that carries a speech to text model of its own and hears Hold to talk with it first. The universal APK is unchanged: it carries no model and its ForgeAsr says it is unavailable. Owner decision, 2026-11-15: Moonshine tiny.

- **The model:** Moonshine tiny, English (MIT; Moonshine's other languages are under a non-commercial licence and are not used), as converted for sherpa-onnx: `csukuangfj2/sherpa-onnx-moonshine-tiny-en-quantized-2026-02-27@d1e6c309`, `encoder_model.ort` 13.3 MB, `decoder_model_merged.ort` 30.4 MB, `tokens.txt` 0.5 MB (44,243,206 bytes).
- **The runtime:** sherpa-onnx v2.0.1 (Apache-2.0, commit `af2d8d81`, 2026-10-26), the release's static build: one `libsherpa-onnx-jni.so` for arm64-v8a, 24,177,488 bytes, with ONNX Runtime 1.28.2 (MIT) linked in; 16 KB aligned. 2.x has no eSpeak NG (GPL). Its Kotlin API files the app needs (`OfflineRecognizer.kt`, `OfflineStream.kt`, `FeatureConfig.kt`, `HomophoneReplacerConfig.kt`, `QnnConfig.kt`) are copied byte for byte from that commit into `android/app/src/privatevoice/java/com/k2fsa/sherpa/onnx/`.
- **Pinned and fetched:** `scripts/asr/lock.json` pins every file (release asset or Hugging Face commit, size, SHA-256); `scripts/asr-model.ts` refuses anything but MIT or Apache-2.0, an unpinned URL, a missing hash or sherpa-onnx before 2.0, downloads what is missing at build time (Gradle task `forgeAsrFiles`, run before every privatevoice build only) and puts the library in `android/app/src/privatevoice/jniLibs/arm64-v8a/` and the model in `android/app/src/privatevoice/assets/asr/moonshine-tiny-en/`; neither is committed. `--check` checks without the network.
- **An ASR-only sherpa-onnx build:** not made. ONNX Runtime is most of the library (the release's shared build: ONNX Runtime 22.2 MB, all of sherpa-onnx's C API 5.1 MB), so leaving out sherpa-onnx's text to speech and other parts could save at most about 2 to 5 MB of 24, and would mean building sherpa-onnx and ONNX Runtime ourselves instead of using the release's checked binary. A minimal ONNX Runtime build with only Moonshine's operators could save more, at the same cost; not tried.
- **Loading:** sherpa-onnx reads the model straight from the APK's assets (`OfflineRecognizer(assets, config)`; the `.ort` files are stored uncompressed, `noCompress 'ort'`), so nothing is copied to the phone's storage. The model loads on the first Hold to talk, while the person starts talking (0.57 to 0.67 s on the Galaxy A16, 1.1 to 1.2 s on the Pixel with another app in front); the sound recorded meanwhile waits and is heard once it is loaded.
- **The process:** the model runs in a process of its own, `:asr` (`AsrService`, declared in the privatevoice manifest only, not exported), bound important by the app. A crash in native code (ONNX Runtime) ends that process, not the app; the plugin then says unavailable for the rest of the session and the next question goes to the phone's recogniser or the engine (as ForgeVoice does). Ending the process is also how the model is let go: every byte comes back.
- **Memory:** about 240 MB peak for the `:asr` process on the Galaxy A16 (VmHWM, 3.5 to 15 s questions), 366 MB on the Pixel. It is let go after a minute with the app in the background, or five minutes with the app open and nothing heard (`AsrRules.RELEASE_BACKGROUND_MS`, `RELEASE_IDLE_MS`); the next Hold to talk loads it again.
- **Recording:** the app records the microphone itself (`AudioRecord`, `VOICE_RECOGNITION`, 16 kHz mono, 100 ms at a time; the same `RECORD_AUDIO` permission, asked by the plugin the first time if the web view has not) and sends the sound to the `:asr` process; nothing is written to storage. At most 90 s (the page stops at 60).
- **Live words:** Moonshine hears whole recordings, so the recording so far is heard again every 500 ms of new sound (the ASR lab's `:s500`), and each result is a `partial`. When a pass takes longer, the next waits for twice that much new sound (`AsrRules.stepAfter`), so a long question keeps the processor busy at most about half the time. Letting go skips any pass not yet started and hears the whole recording once: that is `final`, the question.
- **Threads:** the native voice's rule (`VoiceRules.threads`): as many as the fast cores, at least 2, at most 4; on a phone the natural voice runs on (ARMv8.2), the model's threads are kept on the fast cores (`VoiceRules.pinFor`, through `libforge_ptts.so`'s `pin`). 2 on both test phones.
- **The plugin:** ForgeAsr (`AsrPlugin.kt`, the work in `AsrClient.kt`, rules in `AsrRules.kt`, the model in each flavour's `AsrBundle.kt`). Its calls and events are ForgeSpeech's, so the page handles both alike: `available()` resolves `{available, reason, model, language}`; `start({id})`, `stop({id})`, `cancel({id})`; events `asr` `{id, type}`: `started`, `level {level}`, `partial {text}`, `final {text}`, `error {code}` (`unavailable`, `audio`, `failure`, `interrupted`) and `end`, always last. Reasons it is unavailable: `no speech to text in this app` (the universal APK), `not a 64-bit ARM phone`, `the speech to text files are not in this app`, or the crash or failed load this session.
- **Web side:** `core/native.js` `nativeAsr`; the module `forge.voice-in.bundled` is the phone module over that bridge (the same live words, failures and cancel), listed first. The talk line says "This phone turns it into words", and the question is free as with the phone's recogniser.
- **Checking it on a phone (debug builds):** put a 16 kHz mono WAV in the app's own files and hear it through the same path, fed as a microphone would, then let go; the words and timings go to `adb logcat -s ForgeAsr` (the words only for a check clip, never for the microphone):

  ```sh
  adb exec-in run-as com.forgereserve.ai.privatevoice sh -c 'mkdir -p files/asr-check && cat > files/asr-check/clip.wav' < clip.wav
  # without the app's screen (a foreground service, exported to the adb shell only):
  adb shell am start-foreground-service -n com.forgereserve.ai.privatevoice/com.forgereserve.ai.AsrCheckService -e forge.asrCheck clip.wav
  # or through the Capacitor plugin in the app:
  adb shell am start -n com.forgereserve.ai.privatevoice/com.forgereserve.ai.MainActivity -e forge.asrCheck clip.wav
  ```

## Updating

- A new phonon-tts: change `VERSION` and `INTEGRITY` in `scripts/vendor-phonon.sh` (a version at least 3 days old), run it, run the tests.
- Forge Private Voice's model or sherpa-onnx: edit `scripts/asr/lock.json` (each URL with its commit or release tag, size, SHA-256; a sherpa-onnx release at least 3 days old; the Kotlin API files copied byte for byte from the same commit), update the licence files in `public/vendor/licenses/` (`sherpa-onnx.txt`, `onnxruntime.txt` with the linked version's notices, `moonshine.txt`), and run a privatevoice build and the check above on a phone.
- Another voice or model commit: edit `scripts/phonon/lock.json` (URL with the commit, size, SHA-256), run `node scripts/phonon-model.ts`. A voice for the lab only goes in `labVoices` with `use: "lab-only"` or `"accent-test"`, never in `voices`; a voice the app offers goes in `voices` and needs a line in More, Voice (`voice.natural.<name>` in `strings/en.js`). The model's folder name carries the commit, because the gateway tells phones to keep these files for a year.
